# Ledgerly — Audit & Punch List (2026-05-18)

Snapshot of the codebase at commit `495bdef "stable"` on `main`. Build is clean (Next 16 + Turbopack, all 11 routes, zero TS errors). Working tree clean. Everything below is gap / quality work, not breakage.

---

## P0 — material gaps

### 1. Categories management UI is missing  ✅ DONE (2026-05-20)
The original spec (`readme.md` line 48, pre-rewrite) requires it in Settings. The data layer fully supports it (`src/lib/db/repositories/category.repository.ts`, soft-delete, sync) and `DEFAULT_CATEGORIES` seeds it, but there's no add / rename / recolor / delete UI. The only mention of "categories" in `src/components/settings/settings-content.tsx` is the warning copy at line 628.

### 2. Soft deletes don't propagate across devices via export/import  ✅ DONE (2026-05-20)
`src/lib/db/seed.ts:343` filters `deletedAt != null` out of `exportAllData`, so importing on a second device resurrects records that were tombstoned on the first. Cloud sync handles this correctly; the JSON round-trip doesn't. If anyone is using export/import as their backup story, this is a silent data-loss vector.

### 3. Sync pagination has no `ORDER BY`  ✅ DONE (2026-05-20)
`src/lib/sync/sync-engine.ts:374-403` paginates pulls in 1000-row pages but never calls `.order()`. Supabase doesn't guarantee stable order across `.range()` calls, so rows can be silently skipped or duplicated once a user crosses ~1000 rows per table. Fix: add `.order("updated_at", { ascending: true }).order("id", { ascending: true })`.

## P1 — correctness / sync

### 4. No cascade delete on account / category / merchant
Deleting an account (`src/lib/db/repositories/account.repository.ts`) leaves its transactions, subscriptions, and goals pointing at a dead `accountId`. Same with categories and merchants. Goals do cascade properly (`src/lib/services/goal.service.ts:63`). The UI mostly hides this, but the local DB and cloud diverge silently from the user's mental model. Decide: block deletion if referenced, or cascade soft-delete dependents.

### 5. No FK guards on transaction create
`src/components/transactions/transaction-form.tsx:120` lets you create a transaction with any `accountId`/`categoryId` string — including one that's been deleted in another tab while the form was open. Add a fresh existence check on submit.

### 6. `clearAllData()` hard-deletes locally then sync re-syncs  ✅ DONE (2026-05-20)
`src/lib/db/seed.ts:330` `.clear()`s every table. If sync is enabled, the next pull pulls everything back from cloud (since cloud still has the rows). The "Clear All Data" button likely doesn't behave the way the user expects when cloud sync is on. Either guard the button with a sync-off check, or implement a "clear local AND tombstone remote" path.

### 7. Tie-break ambiguity in conflict resolution
`src/lib/sync/sync-engine.ts:425` keeps local when `remoteUpdatedAt === localUpdatedAt`. With clock skew between devices, simultaneous edits can flip based on sync order. Low impact for a single-user app, but worth a comment documenting the choice.

### 8. v1 → v3 Dexie upgrade backfills only 3 of 6 entity tables
`src/lib/db/database.ts:63-75` backfills `updatedAt` / `deletedAt` for accounts, categories, merchants. Anyone on v1 (no goals existed yet) upgrading straight to v3 is fine for goals (they didn't exist), but transactions / subscriptions / income entries from v1 don't get touched in v3's upgrade either. Worth re-checking; if you ever had real v1 users this matters.

### 9. Soft-delete filters are post-query, not indexed
Every hook (`src/lib/hooks/use-transactions.ts:22`, `use-categories.ts`, etc.) does `.toArray()` then `.filter(t => !t.deletedAt)`. Dexie does have a `deletedAt` index after v3 (`database.ts:50-58`), but it isn't being used. For demo data this is fine; for a user with thousands of transactions it's O(table). Minor unless you expect heavy use.

## P1 — UX

### 10. Merchant model is dead in the UI
Schema has `merchantId` on transactions; demo data populates it; but `transaction-form.tsx` has no merchant select. Either build it or strip merchants from the schema (and `MerchantRepository`).

### 11. No loading skeletons  ✅ DONE (2026-05-20)
`useDashboard`, `useTransactions`, etc. return defaults while Dexie hydrates — pages flash empty for one frame on hard reload. The original spec called for "Beautiful empty states + skeleton loading". Shadcn `Skeleton` component is already exported from `src/components/ui/skeleton.tsx` but isn't used anywhere I saw.

### 12. Archived goals have no-op handlers
`src/app/(app)/goals/page.tsx:153-157` passes `() => {}` for archive / edit / contribute on archived goal cards. The dropdown still shows, so clicks silently do nothing. Either remove the menu for archived cards or wire an "unarchive" action.

### 13. Goal detail "not found" is plain text
`src/app/(app)/goals/[id]/page.tsx` shows a text fallback instead of an `EmptyState` with an icon and back action.

### 14. Required fields are not visually marked
Forms validate via Zod and show errors after submit, but inputs lack `*` markers, so users discover required-ness by failing.

### 15. No "no results" message in transactions list when filters hide everything
Distinguishable from "no data" only by checking filter chips.

## P2 — polish

### 16. Currency is per-account on the schema but global on the formatter
`useCurrencyFormatter` reads the settings-store currency and ignores `account.currency`. Either drop the per-account field or honor it. (UI currently lets you pick a currency per account — purely decorative.)

### 17. Future-dated income is allowed
No bounds on the `MonthSelector` / income form.

### 18. Subscriptions list has no active / paused filter
Despite the schema's `active` boolean.

### 19. No real `README.md`
The file at the repo root was the original AI build prompt. (Rewritten as part of this same pass.)

### 20. Duplicate `package-lock.json`
Build warns it inferred workspace root as `C:\Users\roger\` because of a stray lockfile there. Either delete `C:\Users\roger\package-lock.json` or set `turbopack.root` in `next.config.ts`.

## Considered but dropped (false alarms from auto-audit)

- **Mobile nav doesn't highlight the active route** — false. `src/components/layout/mobile-nav.tsx:42-45` does it correctly via `usePathname()`.
- **`useTransactions` returning `[]` is a "flash empty"** — that's just the documented Dexie-React default, intentional.
- **`use-sync.ts:99` caps backoff to 5 seconds** — false. It caps to the last entry of the backoff array (300s / 5 min), which is correct exponential-backoff-with-ceiling.
- **Sync HWM race that loses rows updated during a sync** — false. `syncStartedAt` is captured before the push query (`sync-engine.ts:136` vs `:340`), so rows updated during the sync are picked up on the next run.
